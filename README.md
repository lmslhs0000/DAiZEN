# DAIZEN 자동차 판매량 예측 v7 — 매달 수집·재학습 포함, 실행에 필요한 파일만

7개 시장(미국·캐나다·유럽·독일·일본·한국·중국) 차종별 월 판매량을 **24개월** 예측한다. 예측 모델은 30개 재료 모델을 세 묶음으로 합치고 차종마다 메타모델 가중치로 섞은 앙상블 **ic_champ**(백테스트 주 점수 25.86%, 작년 그대로 34.13%)이다. 중국은 **CPCA 도매(공장 출하, 수출 포함)** 기준이다.

v2 와 다른 점: 매달 공개 출처에서 새 실적을 모아 원본에 넣고(`step1`), 모델을 처음부터 다시 학습해(`step2`) 새 기준월의 예측을 만들 수 있다. 학습된 재료는 담지 않았다(step2 가 만든다).

v7(2026-10-30): v6 과 모델·예측은 같다. 빈 PC 흉내 시험(설치 → 수집 → 재학습 → 예측)에서 찾은 결함(입력창 없는 실행에서 재학습 마지막 단계가 멈춤)을 고치고, 회사 운영자용 `운영_설명서.md` 를 더했다.

> **운영하는 분은 [`운영_설명서.md`](운영_설명서.md) 부터 보세요** — 컴퓨터 준비 → 설치 → 매달 수집·재학습·예측 출력 → 웹 담당자에게 넘길 파일 → 문제 해결 순서로 적었습니다. 메뉴(`uv run menu.py`)로 하는 법과 파일을 직접 실행하는 법은 [`실행_방법.md`](실행_방법.md) 에 있습니다. 이 README 는 기술 설명(모델·규칙·정확도·한계)입니다.

## 바로 쓰기 (압축을 푼 최상위 폴더에서)

```powershell
uv run --frozen predict.py
```

납품 목록(`raw/deliveries.csv`)의 가장 최근 예측을 `outputs/forecast/`에 쓴다(학습 없음, 몇 초). 지금 최신은 **2026-09 기준 납품(2026-10~2028-09)** 이다 — 2026-10-30 실제 사이트에서 8·9월 실적을 모아 넣고(`step1`) 처음부터 재학습(`step2`, 재료 36/36)한 결과. 2026-07 기준 첫 납품(2026-08~2028-07)도 그대로 들어 있다(`--package` 로 지정). `step2`를 다시 돌리면 그 결과가 최신이 된다.

```text
outputs/forecast/
├─ forecast.json          예측 목록 predictions + 제외 목록 excluded + summary
├─ forecasft_data.csv     6열: Country,Brand,Model,Forecast Month,Horizon,Predicted Sales (제외 차량은 Predicted Sales에 사유)
└─ forecast_detail.csv    상세: 예측값(소수)·80% 범위(lower_80/upper_80)·상태(status_ko)·신뢰도 등급(grade)·과거 오차율(backtest_wape)
```

`Predicted Sales`는 반올림한 정수다. 소수 값·범위·등급은 `forecast_detail.csv`. `raw/vehicle_status.csv`의 상태 명부는 `excluded`에 사유로 들어간다.

## 메뉴로 쓰기 (`uv run menu.py`)

명령을 외우지 않아도 번호로 고를 수 있는 메뉴다. 아래 단계별 파일(step0·step1·step2·predict·backtest.sh)은 그대로 있고 따로 실행해도 된다. 메뉴의 '실행'은 그 파일들을 대신 불러 준다.

| 메뉴 | 하는 일 |
|---|---|
| 1. 점수 보기 | 전체·시장별 백테스트 점수, 차종 검색(과거 오차율·실시간 성적·24개월 예측), 신차 무리 점수 |
| 2. 차종 관리 | 목록에 없는 새 차종 후보, 새 차종 추가, 예측 없는 차종과 이유 |
| 3. 이번 달 성적·경보 | `raw/monitoring.md` |
| 4. 실행 | 0 설치 · 1 수집 · 2 재학습 · 3 예측 출력 · 4 백테스트 (실행 전 예상 시간을 보여 주고 y 로 확인). 재학습·백테스트가 중간에 끊겼으면 이어서 할지 묻는다(끝난 작업은 건너뜀; 입력 자료가 바뀌었으면 처음부터) |
| 5. 설정 보기 | 추정 몫 30% 기준·다시 수집 3개월·실시간 성적 기간 (보기만, 바꾸면 점수가 달라지므로 메뉴에서 바꾸지 않음) |

새 차종 추가: 중국(Gasgoo 차종 페이지 이름)·한국(다나와 미대응 후보에서 고르기)·독일(KBA 브랜드·차종 줄)은 메뉴가 대응표 끝에 한 줄을 넣는다. 같은 차종·같은 출처가 이미 있으면 거부하고, 쓰기 전 `raw/backups/` 에 백업, `raw/mapping_additions.csv` 에 기록한다. 일본·미국·캐나다·유럽은 수집기가 코드 안 표나 원본 목록으로 맞추므로 메뉴가 고칠 파일과 형식을 안내만 한다.

신차 점수: 막 나온 차는 백테스트 구간에 없어 자기 점수가 없다. 대신 백테스트에서 '그 시점의 신차'만 모아 잰 점수가 있다 — 신차 보조 예측(이력 3~11개월) 약 47%, 학습 못 본 차(이력 12개월) 약 48% (본 예측 전체 26%). 차종 자신의 점수는 실적이 3개월 쌓이면 실시간 성적에 생긴다.

## 매달 새 자료로 다시 예측하기

| 단계 | 명령 | 시간 | 하는 일 |
|---|---|---|---|
| 0 (처음 한 번) | `uv run step0_setup.py` | 10~30분 | 파이썬 환경 7개를 고정 버전으로 만들고 점검표(`setup_report.txt`)를 찍는다. 사전학습 모델이 없으면 내려받는다 |
| 1 (매달 말) | `uv run step1_collect.py` | 약 1시간 | 오늘 날짜 기준 빠진 달·채워 둔 달을 모아 원본에 넣고, 지난 예측의 성적(`raw/monitoring.md`)을 매긴다 |
| 2 (1 다음) | `uv run step2_train.py` | 약 5시간(GPU) | 원본+채움으로 재료 모델 30개(학습 작업 36개)를 처음부터 학습 → 조립 → 고객 예측 파일, 납품 목록에 등록 |

필요한 것: Windows, 인터넷, [uv](https://docs.astral.sh/uv/)(파이썬은 uv 가 3.12 를 내려받으므로 따로 설치하지 않아도 됨), [Git for Windows](https://git-scm.com/download/win)(재학습이 Git Bash 를 씀), [Visual C++ 재배포 패키지 x64](https://aka.ms/vs/17/release/vc_redist.x64.exe)(torch 가 씀, 대부분 PC 에 이미 있음), 디스크 여유 30GB(설치 직후 묶음 약 12GB + 재학습마다 약 1.1GB 쌓임, 그 밖에 uv 캐시 약 9GB), 메모리 32GB 권장, NVIDIA GPU + 최신 드라이버 권장(torch CUDA 12.8 판; 없으면 CPU 로 돌게 되어 있으나 시험하지 않음, 재학습이 몇 시간 더 걸림). 재학습 중 절전 모드가 켜지면 멈춘다. VS Code 에서는 파일을 열고 ▶ 로 실행해도 된다(파이썬은 이 폴더의 `.venv`). 2단계 중에는 창을 닫지 않는다.

### 1단계 규칙
- 모을 달: 원본 마지막 달 다음 달 ~ 지난달. 예측·추정으로 채워 둔 달은 최근 3개월만 다시 모은다.
- 넣는 곳:

| 값 | 들어가는 곳 |
|---|---|
| 실제 발표 값, 분기·반기·연 합계를 달로 나눈 값, 한 줄을 여러 차종으로 배분한 값, 유럽 추정값 중 추정 몫 30% 미만 | `raw/data.csv` |
| 추정 몫 30% 이상, 못 구해서 직전 예측으로 채운 값 | `raw/filled_values.csv` (원본과 섞지 않음, 성적 계산 제외, 학습에는 합쳐 씀) |

- 원본에 이미 있는 칸은 다시 조사하지 않는다. 채움 표의 칸만 다시 보고, 실제 값이 나오면 원본으로 옮긴다. 반영 전 `raw/backups/`에 백업.
- 유럽: 상위 약 50개 차종은 Dataforce 유럽 순위(잡지 기사)의 실제 값, 나머지는 나라별 실제 자료 합 + 자료 없는 나라 몫 추정.
- 발표 시기: 중국 차종별은 다음 달 말, 유럽 Dataforce 는 다음 달 22~25일, 캐나다 분기 발표 회사는 분기 뒤 → **매달 말쯤** 실행.
- 모으기만: `uv run step1_collect.py --no-merge`.

### 보고서
- `raw/incoming/<달>/report.md`: 시장별 원본·채움 비율, 목록에 없는 큰 차종, 직전 달보다 3배 넘게 변한 값, 수집기 실패.

- `raw/monitoring_series.csv`: 같은 비교를 **차종마다**(최근 12개 채점 달의 WAPE·작년 그대로·쏠림·등급). 등급 구간은 납품 grade 와 같고(A<20%·B 20-35%·C 35-50%·D 50%+), 실적이 3개월 쌓여야 매긴다. 백테스트 평가가 없던 신차(`평가 없음`)도 이렇게 몇 달 뒤 자기 등급이 생긴다. monitoring.md 아래쪽 '차종별 실시간 성적' 절에 요약. 매달 재학습하면 대부분 1~3개월 앞 예측의 성적이라 백테스트 24개월 점수와 직접 비교하지 않는다.

## 한계
- **확인한 것**(2026-10-16~29, 이 묶음의 사본에서): 설치 → 실제 사이트 수집(7개 시장, 2026-08·09) → 원본 반영 → 재학습(재료 36/36) → 예측; 메뉴 전 기능(새 차종 추가 뒤 실제 수집까지); 다음 달 다시 수집(예측으로 채웠던 칸이 실제 값으로 바뀌고 다른 칸은 그대로); 백테스트(새로 학습해 25.83%, 저장된 챔피언 25.87% 재현, 약 18시간); 끊긴 재학습·백테스트 이어하기; 깃헙에서 새로 받아 설치·예측. 2026-10-30에는 당시 원본으로 만든 이 묶음 사본에서 실제 8·9월 수집 → 재학습 → 예측으로 지금의 2026-09 기준 납품을 만들었다(확인 11/11).
- **빈 PC 흉내 시험**(2026-10-30): 전달 zip 을 띄어쓰기·한글이 든 깊은 경로에 풀고, uv 캐시·파이썬·사전학습 모델 캐시를 모두 빈 폴더로, PATH 는 Windows·uv·Git 만 둔 채 설치(11분) → 예측 출력(묶음 결과와 같음) → 실제 사이트 수집(95분, 오류 0) → 재학습(재료 36/36, 약 5시간) → 예측. 같은 자료로 다시 학습한 결과가 기존 2026-09 판과 소수점까지 같았다(재료 모델 원래 예측값도 같음 — 같은 PC 에서는 재학습이 결정적). 이 시험에서 입력창 없는 실행(작업 스케줄러·숨은 창)일 때 마지막 고객 파일 묶기가 멈추는 결함을 찾아 고쳤다.
- **아직 확인 못 한 것**: 진짜 다른 PC(새 Windows 의 Visual C++ 런타임·다른 그래픽카드와 드라이버·회사 네트워크; 다른 그래픽카드에서는 재학습 결과가 아주 조금 다를 수 있음), GPU 없는 PC 의 재학습 시간, 사이트 구조가 바뀌었을 때의 수집기. 재학습·백테스트가 멈추면 `handover_logs/<production|backtest>/q.log`·`driver.log` 를 본다.
- 못 구한 값은 모델 예측으로 채워 다시 학습한다. 시간이 갈수록 실제 값이 아닌 비중이 커진다(칸 수 기준 2026-08: 직전 예측 14.0%·추정 몫 30% 이상 12.7%, 2026-09: 13.8%·14.0%; 유럽은 대부분 추정). 캐나다(분기 발표 회사)·중국 보류 16개 차종·유럽 상위 50 밖은 구조적으로 채움이 많다.
- 새 차종은 자동으로 들어오지 않는다. 매달 수집 보고서의 '목록에 없는 차종'(독일·유럽·한국만 감지)을 보고 메뉴 2-2 로 넣는다 — 중국·한국·독일은 메뉴가 대응표에 한 줄을 넣고, 일본·미국·캐나다·유럽은 고칠 곳만 안내한다. 넣은 달부터 이력이 쌓여 3개월 뒤 보조 예측, 13개월 뒤 본 예측이 붙는다.
- 출처 의존: 중국은 Gasgoo 한 곳, 미국·캐나다는 GoodCarBadCar 한 곳.
- 유럽 Dataforce 상위 50 은 잡지가 매달 싣지 않는다(2026년 1~4월은 상위 10개뿐).
